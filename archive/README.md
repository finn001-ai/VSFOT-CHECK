## 总结论（截至 2026-10-15）

1. 当前 OT 计划的 argmax ≈ CLIP argmax，任何阶段都没有超过 CLIP；模型准确率被拉到 CLIP 水平后停滞
   （Ar→Cl ≈ 67–68%，Pr→Re ≈ 82%）。
2. 原因：μ_p 取 CLIP 概率的批均值，代价主项是 −log p，Sinkhorn 解 ≈ 锐化的 CLIP，没有理由偏离 CLIP。
3. OT 机制本身有潜力：给定本批真实类分布（oracle μ_p），计划准确率比 CLIP 高 7–12 个百分点。
4. 瓶颈是「无标签地估计本批类边际 μ_p」。
5. 完整训练消融（4 个任务，最后 5 次评估均值）：OT 相对 CLIP 软标签没有稳定增益
   （ot − clip_soft：Ar→Cl +1.2，Pr→Cl −0.9，Re→Cl −0.7，Pr→Re +0.1）。
6. 分解：锐化本身有害（−3 ~ −5 个百分点，clip_sharp ≈ clip_hard），类别边际投影有用（+2.4 ~ +5.2），两者相抵。
   有害的是锐化后批内类别质量被扭曲，而不是单个样本预测太尖锐 —— 类别边际是这个模块真正起作用的部分。
7. 因为 μ_p 取自 CLIP，边际投影最多回到软标签水平；要超过 CLIP 必须改进 μ_p（oracle 上界 7–12 个百分点）。
8. OT 早期收敛更快，三个难任务都在第 748 步达峰后下降 0.9–1.6 个百分点（原因未验证）。

9. **复现性**：公开代码按 README 命令得到 Ar→Cl 67.2%，按论文附录配置得到 64.3%，论文报告 75.0%。
   代码与作者公开仓库逐文件一致，源模型比论文强。公开代码无法复现论文数字；以上所有结论针对公开代码，
   后续以 67.2%（README 命令）为基线。

10. **根本原因（2026-10-15）**：云端图片列表的标签顺序（ASCII 排序，TV 在 Table 前）与 main.py 写死的类名
    （不区分大小写排序）在第 58–63 类错开一位，CLIP 对这 6 类的提示词全部配错。修复后 CLIP 零样本平均 = 79.04%，
    与论文表 4 一致。**第 1–9 条结论都是在类名错位下得到的，需要重新验证。**

12. **类名修复后重做消融（2026-10-15）**：结论不变。OT − 软标签 = +1.11 / −0.99 / −0.41（平均 −0.10），
    锐化 −3.8 ~ −5.8，边际投影 +2.9 ~ +5.8；ot 仍在第 748 步达峰后下降。第 5–8 条在修复后仍然成立。

13. **类名修复后重做诊断（2026-10-15）**：实验 0 和快速诊断结论不变；oracle μ_p 上界变大（7–16 个百分点）。
14. **μ_p 估计器**：所有无标签方法最多把计划拉回到 CLIP argmax，超不过 CLIP（最多 +0.6，且只在模型已超过 CLIP 的阶段）。
    μ_p 从 CLIP 推出时，OT 拿不到 CLIP 以外的信息；「批内改进 μ_p 估计」用简单方法走不通。

15. **全数据集 OT（2026-10-15）**：规模越大越好（批内分布不一致的解释成立），但真实全域边际中后期也只比 CLIP 高 +0.3 ~ +1.6，
    无标签全域边际 ≈ CLIP。**OT 这条线收尾**：所有边际设置下 OT 都超不过 CLIP。
16. **主线结论**：最终准确率 ≈ CLIP 准确率（模型 1/4 进度后追上 CLIP 并一起停滞）。提升的关键是让 CLIP 更准（MGVA / 提示词 / 骨干），而不是改 OT。

17. **研究范围（2026-10-15）**：SFDA 的研究对象是适配本身，不改 CLIP（提示词、骨干等都不考虑）。
18. **目标域结构（2026-10-16）**：学生特征空间里「自身 + 近邻的 CLIP 概率平均」在 6 个快照上全部超过 CLIP
    （Ar→Cl +3.3 / +2.2 / +1.2，Pr→Re +1.6 / +0.6 / +0.2），CLIP 特征空间的同样操作全部为负。第一个属于适配环节的有效信号。

19. **近邻平滑训练（2026-10-16）**：ot_knn10 相对 ot +0.81 / +0.55 / +0.40（Ar/Pr/Re→Cl），但相对 clip_soft 只在 Ar→Cl 更好；
    双向（MGVA 也平滑）−0.42 / −0.59 / +0.25，有害。收益真实但小，单种子。

19. **簇级命名（2026-10-16）**：学生特征簇纯度（K=520）p025 / p050 达 82.5%，高于并集 76–77；但只用 CLIP 命名最好 75.0。
    CLIP 的错误是成簇的系统性错误，簇内投票放大而不是抵消。缺的是一个和 CLIP 错误模式不同的命名员。
    第二轮：用学生 / CLIP×学生命名也到不了并集——学生分类器已被 CLIP 同化（一致率 94%），表示没被同化（纯度 82.5%）。
20. **目标（2026-10-16）**：同设定（CLIP ViT-B/32、ResNet-50）下超过最新公开的 COSMO（Ar→Cl 76.4，Office-Home 平均 86.4，3 个种子）。

21. **独立命名员（2026-10-16）**：冻结源模型给簇命名不行（太弱，47.5%），这条线关闭。
22. **强视图对齐（2026-10-16）**：Ar→Cl 上 ot_knn10_both = 75.98（底座 75.19，COSMO 76.4），而且第一次保住了峰值；
    只用强视图反而更差。突破口在「训练学生的方式」，不在「找别的老师」。
    第 2 轮：Pr→Cl 76.20、Re→Cl 76.04，三个任务都比底座高 0.8–1.6，比原方法高 1.6–2.1；三任务平均 76.07，与 COSMO（76.0）持平略高。

23. **GLC 式全局聚类（2026-10-16）**：老师只排序、学生分配，6 个快照都不如 knn_clip_s；负原型无用。
    救回的共识错误约为近邻平滑的 2 倍，但改坏共识正确的样本多 4–10 倍。换伪标签来源越不过 CLIP 的系统性错误，主线继续强视图。

24. **训练停滞（2026-10-17）**：不是优化问题，是双向蒸馏收敛到共识不动点（伪标签从第 204 步起不比学生好，一致率 → 97%）。
    并集峰值后丢失的 204 个样本中，128 个是「只有学生对」被拉成都错（94 个改成了老师的错误标签）。
    老师 → 学生方向后期零和（学会 110、带错 128），学生 → 老师方向净正（老师学会 108），冻结老师 −0.8；
    12 个 adapter −1.15（塌缩更快），后期混入学生概率无效。566 个最终都错的样本曾被某一方判对过。

25. **表示诊断（2026-10-18）**：停滞在分类器，不在表示。骨干 2048 维特征线性探针 85.0、瓶颈 84.3，比学生高 8–9 个点，
    到训练结束不下降；骨干有效秩不变，瓶颈 210 → 157（90% 维数 132 → 51），学生判错样本附近的瓶颈近邻被同化（锁死样本上近邻标签 34.6 → 23.3）。
    970 个锁死样本约一半线性可分。互近邻 > CSLS > 普通 kNN。基于近邻当前预测的平滑信号后期都在学生 ±0.8 内。
    无标签重拟合分类头（学生 / 老师 / 一致 / 高置信样本作标签）p025 之后全部回到学生 ±0.6；高置信头在锁死样本上只对 7–9%（真实标签探针 52%）：
    锁死错误是系统性的，由当前师生预测导出的任何目标上限都约等于学生。
    锁死错误分散（381 个类对）但多为单向吞并、真实类 47% 排第 2；类边际重分配的上界（真实边际）只有 +2.5，无标签边际估计全部 ≤ 学生。
    结论：后期从当前预测里提不出新信息，改为在源头少继承（对齐权重曲线）。

26. **对齐权重曲线（2026-10-18）**：原方法 min(1, 2·进度) 在老师已不如学生之后才加满。both_cap02（min(0.2, 2·进度)）Ar→Cl 77.00（+1.02，
    超过 COSMO 76.4），第 748 步后曲线继续上升到 77.4；both_const（一直为 1）早期最快但峰值后下降，75.57。单任务单种子，待 run_cap.sh 验证。

11. **复现成功（2026-10-15）**：类名修复后，公开代码 + README 命令在 Ar→Cl 得到 74.4%（论文 75.0%）。
    按论文正文公式实现的版本修复前后都崩溃，说明作者实际用的是公开代码的公式；后续一律以公开代码为基线。
