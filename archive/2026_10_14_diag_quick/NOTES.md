# 快速诊断：μ_p 消融 / 缺席质量位置 / H3 修正（2026-10-14）

## 概要

**为什么做**
实验 0 发现 OT 计划 ≈ CLIP argmax，而且指标都由 μ_p（Sinkhorn 的类别边际）决定，但留下三个疑问：
1. 是 OT 机制本身没用，还是 μ_p 给得不对，导致它只能复述 CLIP？
2. 分给缺席类的质量，是 OT 制造的噪声，还是 CLIP 自己的错误？
3. 实验 0 中 H3 的代价比在后期出现 < 1 的不可能值，真实的缺口到底多大？

**做了什么**
不训练，直接复用实验 0 的 6 个快照，逐批做三件事：
- 只换 μ_p（记忆库 / 当前 CLIP / 均匀 / 真实全域类频率 / 本批真实分布），其余不变，比较计划准确率；
- 把缺席类质量按 CLIP 判对 / 判错的样本拆开，统计计划相对 CLIP 纠正和改坏的样本数；
- H3 的分母改用 gamma1 实际的行 / 列边际重新求精确最优。

**结论**
- 给定本批真实类分布，OT 计划比 CLIP 高 7–12 个百分点；现在的 μ_p 是 CLIP 自己的批均值，所以 OT 只能复述 CLIP。
- 真实的全域类频率反而比现在的 μ_p 差很多，说明 μ_p 必须针对每一批单独估计。
- 70–91% 的缺席质量落在 CLIP 判错的样本上；约 40% 的 CLIP 错误预测的类根本不在本批。
- 早期 OT 改坏的样本多于纠正的，后期大致抵平。
- H3 修正后所有比值 ≥ 1；早期缺口明显（1.35–1.54），到 1/2 进度时 < 1.1。

**证明了什么**
- OT 机制本身有纠错潜力，前提是 μ_p 正确；现在的瓶颈是「不用标签估计本批的类分布 μ_p」。
- 缺席类质量反映的是 CLIP 自身的错误，而不是 Sinkhorn 分配出了问题。
- 实验 0 的 H3 后期数值确实是计算偏差，已修正。

**没有证明的**
- oracle μ_p 用了真实标签，只是上界，实际能拿到多少还要看无标签的 μ_p 估计方法；
- 仍是静态测量，需要完整训练来验证（OT 消融、改进 μ_p 后的训练）。

## 结论

OT 机制本身有用，问题出在 μ_p。给定本批真实类分布，计划比 CLIP 高 7–12 个百分点；
当前 μ_p 是 CLIP 自己的批均值，OT 只能复述 CLIP。

## 对 H1 / H2 / H3 的修正理解

- H1：缺席质量 > 5% 成立，但反映的是 CLIP 自身的错误，而不是 Sinkhorn 分配有问题。
- H2：尺度敏感通过 μ_p 起作用。
- H3：只在训练早期成立。
- 三者都指向同一瓶颈：如何无标签地估计本批类边际 μ_p。
