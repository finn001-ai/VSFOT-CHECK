# GLC 式全局聚类诊断：老师只负责排序，学生特征负责分配（2026-10-16）

> 本诊断是在另一个分支会话里设计并运行的，这份记录是事后根据 `tools/diag_glc.py` 的说明和 `results/summary_all.md` 补写的。

## 概要

**为什么做**
OT 的 μ_p 来自 CLIP 校准过的概率，而 CLIP 的类先验是偏的（全域诊断：L1 ≈ 0.23）；训练在 40%–60% 进度停滞，
老师和学生 94% 的判断一致，剩下的是共享错误。GLC / GLC++（Qu et al., CVPR 2023 / TPAMI）的一对多全局聚类只用类内排序、
每类取相同数量的正样本，不需要估计类先验，可能绕开 CLIP 的先验偏差，并救回共享错误。

**做了什么**
`bash scripts/run_diag_glc.sh` → `tools/diag_glc.py`，`runs/DiagFix/` 的 6 个快照，CLIP 不改动：
每类按 CLIP 概率取前 K 个作为正样本，正原型 = 正样本均值，负样本 K-means 成负原型，
样本离正原型比离所有负原型都近则标为该类。变体：glc_clip（K = N / C）、glc_clip_k0.5、glc_model（原版，排序用学生）、
glc_clip_posonly（只用正原型）、glc_clip_knn（再做局部近邻）；参考 knn_clip_s。
关键指标：共识错误救回（CLIP 和学生都错、该变体对）/ 共识正确改坏（两边都对、该变体错）。

**结论**（±CLIP，百分点）

| 变体 | Ar→Cl p000 / p025 / p050 | Pr→Re p000 / p025 / p050 |
|---|---|---|
| knn_clip_s（参考） | +3.32 / +2.15 / +1.15 | +1.61 / +0.64 / +0.21 |
| glc_clip | −2.68 / +1.37 / +1.03 | −5.16 / −0.30 / +0.05 |
| glc_clip_k0.5 | −3.07 / +1.88 / +1.31 | −6.75 / −0.67 / −0.37 |
| glc_clip_posonly | −3.53 / +1.97 / +1.10 | −5.30 / −0.09 / −0.09 |
| glc_model | −11.55 / +1.72 / +1.03 | −9.30 / −0.05 / −0.07 |

共识错误救回 / 共识正确改坏（Ar→Cl p000 / p025 / p050）：knn_clip_s 94 / 24、46 / 8、15 / 7；glc_clip 209 / 95、85 / 84、26 / 19。

- GLC 救回的共识错误比 knn_clip_s 多（p000 时 209 对 94），但改坏的共识正确也多得多，净效果更差；早期全部为负。
- 中后期在 Ar→Cl 上和 knn_clip_s 接近（+1.0 ~ +2.0），在 Pr→Re 上基本为负。
- 负原型的作用不明显（posonly 和完整版接近）。

**证明了什么**
- 「只用排序、不估计类先验」的全局聚类能救回更多共识错误，但代价是破坏更多原本正确的判断，整体不如简单的近邻平滑。
- 共识错误不能靠全局聚类在静态下净救回，和簇级命名诊断（`../2026_10_16_diag_cluster/`）的结论一致。

**没有证明的**
- 静态测量；未接进训练。
