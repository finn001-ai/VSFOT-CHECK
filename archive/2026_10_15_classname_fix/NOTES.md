# 类名与标签错位：复现差距的根本原因（2026-10-15）

## 概要

**为什么做**
公开代码在 Ar→Cl 上只有 67.2%（论文 75%）。核对论文正文后发现：论文表 4 中 CLIP（ViT-B/32）在 Office-Home 的零样本平均为 79.04%，
而我们诊断时测得的 CLIP 准确率明显更低。论文图 3 和我们的实验都表明，最终准确率会收敛到 CLIP 附近，
所以先确认 CLIP 起点是否和论文一致。

**做了什么**
写 `zeroshot_clip.py`：用原始 CLIP ViT-B/32（无 adapter、不训练），在四个域上测零样本准确率，
并核对「图片列表中每个标签对应的类文件夹名」与代码使用的类名是否一致。

**结论**
1. 云端图片列表（`/hyperai/input/input0/*_list.txt`，路径为绝对路径）的标签顺序是按 ASCII 排序的
   （大写 TV 排在 Table 前），而 main.py 写死的类名按不区分大小写排序。第 58–63 类错开一位：

   | 标签 | 云端列表（真实） | 原 main.py 提示词 |
   |---|---|---|
   | 58 | TV | Table |
   | 59 | Table | Telephone |
   | 60 | Telephone | ToothBrush |
   | 61 | ToothBrush | Toys |
   | 62 | Toys | Trash_Can |
   | 63 | Trash_Can | TV |

2. 类名错位时零样本平均：72.21%（下划线）/ 72.69%（空格）：Ar 72.1、Cl 57.7、Pr 80.0、Rw 79.1。
3. 改为从 `classname.txt` 读取类名（与列表标签一致）后，零样本平均 = **79.04%，与论文表 4 完全一致**。

**证明了什么**
- 论文的 CLIP 基线可以复现；我们 CLIP 起点偏低的根本原因是类名与标签错位，不是 CLIP 骨干、提示词下划线或训练配置。
- 之前所有实验（实验 0、快速诊断、三轮消融、论文配置、论文公式）中，第 58–63 类的 CLIP 提示词都是错的，
  CLIP 对这 6 类的指导（OT 计划、μ_p、MGVA）全部错误。这些实验的结论需要在修复后重新验证。
- 源模型不受影响（源模型训练只用标签编号，和适配阶段用的是同一套列表）。

**训练结果（`run_ac.sh`，Ar→Cl，seed 42，最后 5 次评估均值）**

| 组 | 配置 | 类名修复前 | 类名修复后 | 论文 |
|---|---|---|---|---|
| code_readme | 原公开公式 + README 命令（40 epoch） | 67.2 | **74.4**（最终 74.5，峰值 75.0） | 75.0 |
| paper_cfg | 论文公式 + 附录超参（20 epoch） | 9.3 | 12.9（第 1 个 epoch 41.1 后崩溃） | - |

- 只修类名，公开代码就从 67.2 涨到 74.4，与论文 75.0（3 个种子平均）只差 0.6 个百分点，**复现成功**。
- 论文公式版本修复前后都崩溃，崩溃与类名错位无关，是我们对论文公式的实现 / 解读与作者的真实做法不一致。
  作者的数字是用公开代码的公式得到的，所以后续一律以 `--formula code` + README 命令为准（main.py 默认已改为 code）。

**没有证明的**
- 只有 1 个任务、1 个种子；其余 11 个任务未跑。
- 论文公式为什么崩溃没有查（不再追究）。
