# 按论文附录配置复现 Ar→Cl（2026-10-15）

## 概要

**为什么做**
之前所有实验中，`ot`（原方法）在 Ar→Cl 上只有 67.2%，论文报告 75.00%，差距约 8 个百分点。
需要确认差距来自哪里，避免后续研究建立在错误的基线上。

**做了什么**
1. 读论文附录（`paper_supplemental.pdf`，CVPR 2026 supplemental，第 4 节实现细节），逐项和代码对照：

   | 项目 | 附录 | 公开代码默认 / README 命令 |
   |---|---|---|
   | CLIP 骨干 | ViT-B/32 | ViT-B/32（一致） |
   | 批大小 | 64 | 64（一致；最初提交的 main.py 默认 32，已改为 64） |
   | Sinkhorn ε / 迭代 | 0.2 / 1e3 次 / 1e-9 | 同（一致） |
   | adapter 层数 | 最后 3 层 | 3（一致） |
   | 模型 SGD | momentum 0.9，wd 5e-4 | 纯 SGD，无动量无 wd |
   | adapter Adam | wd 1e-4 | 无 wd |
   | adapter 隐藏维度 | 64 | 256 |
   | Office-Home epoch | 20 | 40 |
   | 结果 | 3 个种子平均 | — |

2. `main.py` 新增 `--momentum --wd --adam_wd --adapter_dim`（默认值 = 原代码行为），
   `run_paper_cfg.sh` 按附录配置跑 Ar→Cl `ot`，种子 42，20 epoch。
3. 用训练日志第 0 步的逐类准确率，按类图片数加权，计算源模型准确率。
4. 下载作者公开仓库 `github.com/TangXu-Group/VSFOT`（只有 main 分支，无 README 所说的 `model` 分支），
   和本项目最初提交 `519c4cd` 逐文件比对。

**结论**

| 配置 | Ar→Cl（最后 5 次评估均值） |
|---|---|
| 公开代码 + README 命令（40 epoch，纯 SGD，adapter 256） | 67.2% |
| 公开代码 + 附录配置（20 epoch，momentum 0.9，wd，adapter 64） | 64.3% |
| 论文报告（3 个种子平均） | 75.0% |

附录配置训练曲线：68:0.6021 408:0.6202 748:0.6408 1088:0.6426 1359:0.6410（早期更快，平台更低）。

- 源模型比论文强：Ar→Cl 48.4%（论文 45.86），Pr→Cl 35.9%（32.79），Re→Cl 48.2%（44.34）。
  之前说的「约 42%」是诊断时用 BN 训练模式测的，不代表源模型准确率。
- 本项目代码和作者公开代码逐文件完全相同（只差 `.DS_Store`），不是复制或改写出错。
- 按附录配置结果更差，附录写明的超参数不是差距来源。

**证明了什么**
- 用作者公开代码、按论文附录写明的设置，复现不出论文的 75%。
  论文实验所用的代码或配置，很可能与公开版本不同，且差异未在附录中写明。
- 之前的诊断和消融分析的是「公开代码的实际行为」，结论本身仍成立，但不代表「得到 75% 的那个版本」。
- 后续以 67.2% 配置（README 命令）作为可复现基线。

**没有证明的**
- 只有 1 个种子；但种子波动通常约 1 个百分点，不足以解释 8–11 个百分点的差距。
- 学习率含义（附录「初始 1e-3」vs 代码 bottleneck 1e-2）、提示词类名含下划线（`a photo of a Alarm_Clock`）
  这两处未验证。

## 补充：论文正文与代码核对（`paper_main.pdf`）

**CLIP 零样本基线对不上（最可疑）**：论文表 4 中 CLIP（ViT-B/32）在 Office-Home 的零样本平均为 79.04%；
我们诊断时测得 Clipart 57.7%、Real World 79.1%，四个域平均不可能到 79%。
论文图 3 也说明模型和 VLM 最终收敛到相近准确率，所以 CLIP 起点偏低会直接拉低最终结果。
嫌疑：提示词类名带下划线（`a photo of a Alarm_Clock`），常见做法是替换为空格。

**公式与代码不一致**：

| # | 论文 | 代码 | 影响 |
|---|---|---|---|
| 1 | 式 3：Cv = α(1 − q^v) + L(q^m, y_j)，第二项为模型交叉熵 | `getGamma`：α(1 − clipProb) − log(clipProb)，第二项用 CLIP | 大：代码的计划完全由 CLIP 决定，即「计划 ≈ 锐化的 CLIP」 |
| 2 | 式 2：L_Align = Σ Γ*·Cm | gamma1 先乘 1/类频率 | 中，论文未提 |
| 3 | 式 13：各损失权重为 1 | 对齐损失权重 min(1, progress × 2) | 中，论文未提 |
| 4 | 式 11：只在保留的 top-k 上归一化 | 归一化 → ×10 → 对全部 65 类 softmax | 小到中 |
| 5 | 式 6：μ_p = 当前批 CLIP 预测均值 | 记忆库均值 | 很小（快速诊断差距 < 0.4 个百分点） |

一致的：Cm（式 1）、L_IM（式 9）、KL 方向（式 12）、ε = 0.2、top-k = 3、adapter 放在最后 3 层。
与我们的结果吻合：论文表 5 中 μ_p 换为均匀分布下降 11.72 个百分点。
